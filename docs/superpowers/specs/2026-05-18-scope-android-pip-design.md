# Scope Android (PiP) Design

**Status:** Brainstormed; awaiting plan-reviewer pass and user review of this spec.
**Date:** 2026-05-18
**Project root:** `~/software/oscilloscope/`
**Builds on:** [2026-05-16-music-oscilloscope-design.md](2026-05-16-music-oscilloscope-design.md)

## 1. Summary

Package Scope as an Android APK so the visualiser can run on a phone with **system audio loopback** instead of `getDisplayMedia` tab capture. The existing PixiJS render pipeline (waveform, spectrum, Lissajous, three themes) is reused unchanged; only the audio-input layer and the controls UI are platform-specific. The app runs full-screen during interaction and auto-enters **Picture-in-Picture** when the user backgrounds it, so the visualiser stays visible while another app (Spotify, YouTube Music) plays in the foreground. Distribution is **sideload-only**, self-signed APK.

## 2. Goals and non-goals

### Goals
- Reuse the existing rendering code (`drawWaveform`, `drawSpectrum`, `drawLissajous`, themes, RenderTexture trail) without modification.
- Capture system audio via `AudioPlaybackCapture` (Android 10+ API; targeting Android 14+ specifically).
- Keep the existing web build working unchanged for desktop browsers; platform detection picks the audio source.
- Touch-first mobile UI: full-screen canvas, swipe-right to cycle views, swipe-left to open a settings drawer.
- Auto-enter PiP on `onUserLeaveHint`. PiP shows the canvas only, with one system RemoteAction button (cycle view).
- Self-signed APK built with `./gradlew assembleRelease`. Sideload by HTTP download.

### Non-goals
- Tab-share style audio routing on Android. Tab audio capture (the desktop `getDisplayMedia` model) does not exist on Android Chrome.
- Microphone fallback for older Android. The min API is hard-set at 34 (Android 14).
- Google Play Store, F-Droid, or any review-gated channel.
- Tablet-specific layouts. Phone form factor only.
- Capture of DRM-protected audio (Netflix, certain DRM streams). `AudioPlaybackCapture` is silently denied for protected content; the UI surfaces a "no signal" hint, same as the desktop edge case.
- Background-without-PiP capture. If PiP is unavailable (system disabled), capture stops on background instead of running silently.
- iOS. Apple does not expose system audio loopback to apps under any policy.
- Accessibility audit (TalkBack, large-text). Deferred.

## 3. Architecture overview

```
oscilloscope/
├── index.html              ← unchanged (mobile CSS is in style.css)
├── main.js                 ← modified: platform-detected audio path + mobile UI
├── style.css               ← modified: mobile classes (settings drawer, fullscreen canvas)
├── pixi-shim.js            ← unchanged
├── manifest.webmanifest    ← unchanged (still used by PWA fallback)
├── audio-worklet-processor.js  ← new: AudioWorklet source consuming PCM chunks
│
├── capacitor.config.json   ← new: appId, webDir, plugins config
├── package.json            ← new: capacitor deps
├── android/                ← new, generated by `npx cap add android`
│   ├── app/
│   │   ├── src/main/
│   │   │   ├── AndroidManifest.xml
│   │   │   └── java/com/alpapan/scope/
│   │   │       ├── MainActivity.kt           ← extends BridgeActivity; PiP wiring
│   │   │       ├── ScopeAudioPlugin.kt       ← Capacitor plugin
│   │   │       ├── AudioCaptureService.kt    ← foreground service
│   │   │       └── ScopePipReceiver.kt       ← BroadcastReceiver for PiP cycle-view button
│   │   └── build.gradle
│   └── build.gradle
└── docs/superpowers/specs/2026-05-18-scope-android-pip-design.md  ← this file
```

Three layers:

**Web layer** (HTML/CSS/JS). Existing render code is untouched. `main.js` gains a platform-detected entry path: on Android (`typeof Capacitor !== 'undefined' && Capacitor.getPlatform() === 'android'`), the audio graph is built around an `AudioWorkletNode` source instead of `MediaStreamSource`, and the controls panel is replaced by a touch-driven settings drawer.

**Capacitor bridge** (Kotlin). One custom Capacitor plugin (`ScopeAudio`) with two methods (`startCapture`, `stopCapture`) and one event (`audioChunk`). The plugin owns the `MediaProjection` permission flow and a binding to the audio capture service.

**Native Android** (Kotlin). A foreground service of type `mediaProjection` runs `AudioPlaybackCaptureConfiguration` + `AudioRecord` on a reader thread, batches PCM into 1024-stereo-frame chunks, and posts them to the plugin. A `MainActivity` extending Capacitor's `BridgeActivity` configures PiP and forwards the RemoteAction broadcast into JS.

## 4. Audio pipeline (Android)

On user tap of **Start capture**:

```
ScopeAudioPlugin.startCapture()
        │
        ▼ MediaProjectionManager.createScreenCaptureIntent()
System dialog: "Allow Scope to start capturing what's on your screen?"
        │
        ▼ on Start now
MediaProjection
        │
        ▼ startForegroundService(AudioCaptureService)
AudioPlaybackCaptureConfiguration
   .Builder(mediaProjection)
   .addMatchingUsage(USAGE_MEDIA)
   .addMatchingUsage(USAGE_GAME)
   .addMatchingUsage(USAGE_UNKNOWN)
   .build()
        │
        ▼
AudioRecord:
  sampleRate = 48000
  channelConfig = CHANNEL_IN_STEREO
  audioFormat = ENCODING_PCM_FLOAT
        │
        ▼ reader thread: 1024-frame stereo chunks (= 2048 floats interleaved)
ScopeAudioPlugin.onPcmChunk(floatArray)
        │
        ▼ base64-encoded interleaved Float32 bytes
notifyListeners("audioChunk", {data: <Base64>})
        │
        ▼ JS event listener
new Float32Array(base64DecodeToBytes(data).buffer)
        │
        ▼ workletNode.port.postMessage(interleaved, [interleaved.buffer])
AudioWorkletProcessor:
  ring buffer (8192 frames × stereo)
  process(): drain 128 frames into output channels[0], channels[1]
        │
        ▼
ChannelSplitter (Web Audio, downstream from worklet)
        ├──► AnalyserNode (left)
        └──► AnalyserNode (right)
                ↑ same fftSize / smoothingTimeConstant controls as desktop
```

Notes:
- The worklet is the **source node**: it generates output samples from the ring buffer. Downstream is the same `ChannelSplitter → AnalyserL/AnalyserR` graph as desktop, so `drawWaveform`/`drawSpectrum`/`drawLissajous` read from the same analyser API and need zero changes.
- **Graph must terminate at `ctx.destination` via a zero-gain sink.** Unlike desktop's `MediaStreamSource` (which actively pushes samples into the graph), an `AudioWorkletNode` used as a source only has `process()` called reliably when the graph has a path to `ctx.destination`. We therefore add: `analyserL.connect(silenceGain); analyserR.connect(silenceGain); silenceGain.connect(ctx.destination)` where `silenceGain = ctx.createGain(); silenceGain.gain.value = 0`. The destination receives silence (no audible double-output), but the rendering thread processes the chain so the analysers update. This is the standard Web Audio idiom for "active graph, no audio out".
- Sample-rate matching: `AudioContext` defaults to the device output rate (typically 48000 on modern Android). We force the `AudioContext` constructor with `{sampleRate: 48000}` to match the capture rate; if the device refuses, we fall back to the device default and add a sample-rate-conversion stage in the worklet (linear interpolation; quality is adequate for visualisation).
- Capture usage filtering: `addMatchingUsage(USAGE_MEDIA | USAGE_GAME | USAGE_UNKNOWN)`. Voice calls and notification sounds are excluded so they do not pollute the visualisation.
- DRM content: `AudioPlaybackCapture` silently delivers zero samples for apps that opt out (or for protected media). Our "no signal" hint covers this transparently.
- The reader thread uses **`AudioRecord.read(FloatArray, offset, size, READ_BLOCKING)`** so the loop blocks on data availability without busy-waiting. Chunk size is 1024 stereo frames (~21 ms at 48 kHz) which keeps latency low without saturating the JS bridge.

**Why Base64, not raw bytes?** Capacitor's `notifyListeners` JSON-serialises its payload. Float32 arrays do not survive JSON. Base64 inflates the payload by ~33% (8 kB binary → 11 kB string) but Bridge-to-JS string transit is fast, and decoding happens once per chunk. If throughput proves to be a bottleneck during implementation testing, the **fallback** is a local WebSocket on `127.0.0.1:<random-port>` carrying raw binary frames; the plugin would expose the port via `startCapture`'s return value and JS would connect immediately after. This is **not the initial path** because it adds non-trivial Kotlin plumbing (socket lifecycle, port allocation).

## 5. Render pipeline

**Unchanged from the desktop design.** The PixiJS application, RenderTexture trail, scene graph, per-frame loop, filter application, resize handling, and HiDPI handling all work identically on Android. The Android WebView is Chromium-based and supports WebGL 2.

The only render-side adaptation: the canvas fills the entire viewport including under the status bar (immersive fullscreen). CSS `body { padding: env(safe-area-inset-top) env(safe-area-inset-right) env(safe-area-inset-bottom) env(safe-area-inset-left); }` is applied only to the **controls layer**, not the canvas, so the visualisation extends edge-to-edge while the settings drawer respects the cutout/notch.

## 6. The three views

**Unchanged from the desktop design.** All formulas, trigger logic, frequency mapping, and rotated Lissajous convention apply identically. The analyser API is the same regardless of source.

## 7. Mobile UI shell

### Platform detection and CSS toggling

```js
const isAndroid = typeof Capacitor !== 'undefined'
  && Capacitor.getPlatform() === 'android';
document.body.classList.toggle('mobile', isAndroid);
```

CSS uses `body.mobile` and `body.pip` as feature toggles:

```css
body.mobile #controls       { display: none; }    /* desktop panel hidden */
body.mobile #mobile-start   { display: flex; }    /* start screen variant */
body.mobile #mobile-drawer  { display: flex; }    /* settings drawer */
body.pip    #mobile-start,
body.pip    #mobile-drawer,
body.pip    #mobile-toast   { display: none; }    /* in PiP: canvas only */
```

### Start screen (mobile variant)

```
┌─────────────────────────────────────┐
│                                     │
│           ╱╲    SCOPE               │
│          ╱  ╲                       │
│         ╱    ╲                      │
│                                     │
│   ┌─────────────────────────────┐   │
│   │       Start capture         │   │
│   └─────────────────────────────┘   │
│                                     │
│   Tap Start, allow screen           │
│   capture, then open your music     │
│   app and play something.           │
│                                     │
└─────────────────────────────────────┘
```

- One large primary button (44 dp+ tap target, full-width minus 32 dp gutters).
- Instructional copy below explains the MediaProjection permission dialog the user is about to see (so it does not surprise them).
- Themed background matches the active theme `--bg` and accent matches `--fg`.

### Capture screen (mobile)

Full-screen canvas. No persistent controls. A small transient toast in the top-centre shows the current view name for ~1.5 s after a swipe ("Waveform", "Spectrum", "Lissajous").

### Settings drawer

Slides in from the **right edge** when the user swipes **left** on the canvas. Width = 80% of viewport on phones, capped at 360 dp on wider screens.

```
┌──────────────────┐
│                  │
│   Theme          │
│   ┌────┬────┬────┤
│   │CRT │NEON│MONO│  ← three large chip buttons
│   └────┴────┴────┤
│                  │
│   Sensitivity    │
│   ●────────────  │  ← large slider thumb
│                  │
│   FFT size       │
│   ◀ 2048 ▶       │  ← segmented stepper
│                  │
│   Smoothing      │
│   ─────●──────   │
│                  │
│   ┌────────────┐ │
│   │    Stop    │ │  ← prominent red/themed
│   └────────────┘ │
│                  │
└──────────────────┘
```

- Theme: three chip buttons; the active one is highlighted with the theme's `--fg` colour.
- Sensitivity: large slider, range 0.1 to 4.0, step 0.1.
- FFT size: segmented stepper (◀ value ▶) cycling through 256/512/1024/2048/4096/8192/16384/32768. Avoids a native picker because the option count is fixed and small.
- Smoothing: slider, range 0 to 0.95, step 0.05.
- Stop: full-width button; tapping stops capture and returns to the start screen.
- Backdrop: semi-transparent black behind the drawer; tap to dismiss.

### Gestures

Touch events bound to `canvas#stage` (Hammer.js is **not** added; a small inline handler is sufficient and avoids a dep):

```
touchstart  → record (x, y, t)
touchmove   → no-op
touchend    → compute (dx, dy, dt)
              if |dx| > 40 && |dx| > |dy| * 1.5:
                  dx > 0:  cycleView(+1)    ← swipe right
                  dx < 0:  openDrawer()      ← swipe left
              else:
                  no-op (treat as tap or noise)
```

When the drawer is open, the same handler on the drawer's backdrop closes it on swipe-right or tap.

**Edge swipes** (from within 16 dp of the left or right screen edges) are ignored by our handler so Android's back-gesture wins. Practically: a swipe that starts inside the canvas but not at the very edge cycles or opens; a swipe that starts at the edge triggers system back.

### Back-gesture handling

System back (gesture or button):
- If the settings drawer is open → close drawer, do not exit.
- If in PiP → handled by system (expand or dismiss).
- If capturing → call `stopCapture()`, return to start screen.
- If on start screen → exit app (default OS behaviour).

Wired via Capacitor's `App.addListener('backButton', ...)` API.

## 8. State and controls (mobile)

Same `state` object as desktop. Three writers:

- `startCapture()` (rewritten path):
  - Android branch: `await ScopeAudio.startCapture()` (waits for permission grant); construct `AudioContext`, register and instantiate the audio worklet, wire the rest of the graph; subscribe to `ScopeAudio.addListener('audioChunk', ...)`; set `state.running = true`; hide start screen; kick rAF.
  - Desktop branch: unchanged (`getDisplayMedia` path).
- `stopCapture()`: same idempotent semantics. Android branch additionally calls `await ScopeAudio.stopCapture()` which stops the foreground service.
- `applyState()`: unchanged.

New helpers:
- `cycleView(direction)`: advances `state.view` through `['waveform', 'spectrum', 'lissajous']`, wraps; flashes the toast.
- `openDrawer()` / `closeDrawer()`: toggles `body.drawer-open` class; slides the panel.

Event wiring on Android replaces the dropdown `onchange` handlers with drawer-control listeners (chip taps, slider input, segmented stepper buttons). The hotkey handler is unchanged but unreachable in Android (no keyboard); we keep it for desktop only.

## 9. Picture-in-Picture

### Entry

`MainActivity.onUserLeaveHint()` fires when the user explicitly leaves the app (home, recents, or another app launch). If `state.running` is true at that moment, the activity enters PiP:

```kotlin
override fun onUserLeaveHint() {
    if (isCapturing) {
        val params = PictureInPictureParams.Builder()
            .setAspectRatio(Rational(16, 9))
            .setActions(listOf(buildCycleViewAction()))
            .build()
        enterPictureInPictureMode(params)
    }
}
```

`isCapturing` is a boolean held on `ScopeAudioPlugin` itself, flipped to `true` when `startCapture` succeeds and back to `false` when `stopCapture` runs. `MainActivity` reads it directly from the plugin instance - no separate sync method needed because the plugin already owns both transitions.

`onPictureInPictureModeChanged(isInPip, ...)` is the cross-side signal: the activity calls `webView.evaluateJavascript("document.body.classList.toggle('pip', " + isInPip + ")", null)` on the Capacitor bridge's WebView. The CSS hides drawer, toast, and start screen; canvas remains visible and fills the PiP window via the existing `resizeTo: window` setup.

### Exit

The user expands the PiP window (drag, tap, system gesture) and the activity returns to its normal lifecycle. `onPictureInPictureModeChanged(false)` removes the `pip` class. Capture continues uninterrupted.

If the user dismisses the PiP window entirely (swipe-out), `onStop()` fires. We call `stopCapture()` to release the `MediaProjection` and the foreground service.

### RemoteAction (cycle view button)

The PiP header shows one system-rendered icon button. Tapping it broadcasts a `PendingIntent` that lands in `ScopePipReceiver`:

```kotlin
class ScopePipReceiver : BroadcastReceiver() {
    override fun onReceive(ctx: Context, intent: Intent) {
        if (intent.action == ACTION_CYCLE_VIEW) {
            ScopeAudioPlugin.instance?.bridge?.webView
                ?.evaluateJavascript("window.cycleView && window.cycleView(1)", null)
        }
    }
}
```

`window.cycleView` is a global exported from `main.js`. `ScopeAudioPlugin.instance` is a static back-reference set in the plugin's `load()`, used only for this purpose.

The action icon is `ic_skip_next_24` (system-equivalent). Label: "Next view".

### Manifest declarations

```xml
<activity
    android:name=".MainActivity"
    android:supportsPictureInPicture="true"
    android:resizeableActivity="true"
    android:configChanges="screenSize|smallestScreenSize|screenLayout|orientation"
    ... />
```

`configChanges` is critical: without it the activity (and the WebView, and the WebGL context, and the AudioContext) all recreate on PiP transition, destroying the running visualisation. With it, the activity stays alive and just re-flows the layout.

## 10. Permissions and manifest

```xml
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PROJECTION" />
<uses-permission android:name="android.permission.INTERNET" />

<application>
    <activity
        android:name=".MainActivity"
        android:exported="true"
        android:supportsPictureInPicture="true"
        android:resizeableActivity="true"
        android:configChanges="screenSize|smallestScreenSize|screenLayout|orientation"
        android:launchMode="singleTask"
        android:theme="@style/AppTheme.Splash">
        <intent-filter>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LAUNCHER" />
        </intent-filter>
    </activity>

    <service
        android:name=".AudioCaptureService"
        android:foregroundServiceType="mediaProjection"
        android:exported="false" />

    <receiver
        android:name=".ScopePipReceiver"
        android:exported="false" />
</application>
```

`INTERNET` is required so the WebView can load any CDN assets if used (and Capacitor's local bridge over `https://localhost`).

`RECORD_AUDIO` is required by `AudioPlaybackCapture` even though we are not recording the microphone. Android grants it implicitly because the `MediaProjection` consent dialog covers the screen+audio permission, but the manifest declaration is required for the API to function.

`FOREGROUND_SERVICE_MEDIA_PROJECTION` is the Android 14 (API 34) requirement that specialises the foreground service type. Without it the service fails to start on API 34+.

## 11. Build and signing

### Tooling

- Node.js 18+ (for Capacitor CLI; not a runtime dependency).
- JDK 17 (Android Gradle Plugin requirement).
- Android SDK with build-tools 34.x, platform-tools, and platform 34.
- Android Studio recommended for IDE, but not strictly required.

### One-time setup

```bash
cd ~/software/oscilloscope
npm init -y
npm install --save-dev @capacitor/cli
npm install --save @capacitor/core @capacitor/android
npx cap init Scope com.alpapan.scope --web-dir .
npx cap add android
# write plugin files into android/app/src/main/java/com/alpapan/scope/
# edit android/app/src/main/AndroidManifest.xml per §10
keytool -genkey -v -keystore ~/.android/scope-release.keystore \
    -alias scope-key -keyalg RSA -keysize 4096 -validity 10000
```

`capacitor.config.json`:

```json
{
  "appId": "com.alpapan.scope",
  "appName": "Scope",
  "webDir": ".",
  "server": {
    "androidScheme": "https"
  }
}
```

`webDir: "."` means Capacitor copies the repo root (HTML/CSS/JS) directly. No bundler step. The same files served by `python3 -m http.server 8000` are the ones embedded in the APK.

### Per-build

```bash
npx cap sync android
cd android
./gradlew :app:assembleRelease
# output: android/app/build/outputs/apk/release/app-release.apk
```

`gradle.properties` references the keystore for release signing:

```
SCOPE_KEYSTORE_FILE=~/.android/scope-release.keystore
SCOPE_KEYSTORE_PASSWORD=<filled at first build, kept locally>
SCOPE_KEY_ALIAS=scope-key
SCOPE_KEY_PASSWORD=<filled at first build, kept locally>
```

`app/build.gradle` signing config reads from `gradle.properties`. The keystore file itself is **not** checked into git; the path is documented in `docs/manual-qa.md` and the README.

### Sideload

The APK is published as an artefact in one of:
- a static file on the laptop's `python3 -m http.server` (already running for the web build): drop into `oscilloscope/`, download from phone at `http://<lan-ip>:8000/app-release.apk`.
- a GitHub release asset (`gh release create v0.1.0-android android/app/build/outputs/apk/release/app-release.apk`).
- Nextcloud or any cloud drive.

The phone needs "Install unknown apps" enabled for whichever browser/file-manager is doing the install. One-time setting per app source.

### Update flow

Bump `versionCode` in `android/app/build.gradle`, rebuild, redistribute. Phone tap-installs the new APK; Android upgrades in place if the signing key matches.

## 12. Errors and edge cases

| Condition | Detection | User-facing message |
|---|---|---|
| User denies MediaProjection permission | `ScopeAudio.startCapture()` rejects with `PERMISSION_DENIED` | "Capture cancelled. Tap Start again to retry." |
| Foreground service fails to start | Service `onStartCommand` returns error; plugin rejects | "Could not start audio capture. Restart the app and retry." |
| DRM-protected source | `AudioRecord.read` returns zero or near-zero samples for >3 s | Inline hint: "No signal detected. Some apps block capture (DRM)." |
| Source app is muted | Same time-domain near-zero detection | Same hint. |
| User dismisses PiP window | `onStop()` | Capture stops cleanly; relaunching the app shows the start screen. |
| Phone runs out of memory mid-capture | Ring buffer overrun; underrun = zero samples in worklet | Underflow is silent; the visualiser shows zero amplitude until catch-up. No error UI. |
| Audio focus loss (call comes in) | `AudioManager.OnAudioFocusChangeListener` fires `LOSS_TRANSIENT` | We do **not** pause capture (we are not playing audio). The source app handles its own focus. |
| `AudioContext.sampleRate` not 48000 | Compared on init | Linear resample in the worklet. |
| Android < 14 install attempt | Min SDK in manifest | Install rejected by Android; user sees "App not compatible with your device". |
| Capacitor bridge JSON throughput insufficient | Manual observation during QA: visualiser stutters or chokes | Fallback to local-WebSocket bridge (see §4). Not the initial implementation. |
| Activity recreated despite `configChanges` | `onCreate` runs while `state.running` was true on JS side | JS detects mismatch (Capacitor `ready` event fires twice without `startCapture` in between) and calls `stopCapture()` to reset cleanly. |

### Explicitly out of scope

- Resume on next launch (no persistence of running state).
- Bluetooth audio routing (capture follows the system mix; if Bluetooth output is active, captured audio mirrors what the user hears).
- Capture during phone calls (system blocks `USAGE_VOICE_COMMUNICATION`, which is the desired behaviour).

## 13. Testing

### Automated

- Existing `tests/helpers.test.js` (`freqToX`, `findZeroCrossing`) continues to pass under `node --test`; no changes.
- **New:** `tests/audio-ring-buffer.test.js` - pure-JS test of the worklet's ring buffer:
  - `write` then `read` returns identical samples
  - overflow drops oldest data (or pauses writes, per chosen policy)
  - underflow returns zeros
  - read/write across the wrap boundary returns contiguous samples
- **New:** `tests/swipe-detector.test.js` - pure-JS test of the touch-classification helper:
  - horizontal-dominant motion + sufficient magnitude → "right" or "left"
  - vertical-dominant motion → "none"
  - tiny motion → "none"

Both new test files are plain `node --test`, no DOM, no mocks of our own code (project rule).

### Manual QA

Append a new section to `docs/manual-qa.md`: **Android sideload**.

1. Install the APK on a phone with Android 14+; launch.
2. Tap Start capture; allow screen capture; open Spotify; play a song.
3. Verify the waveform renders.
4. Swipe right twice: waveform → spectrum → Lissajous; toast appears each time.
5. Swipe left: settings drawer slides in from the right. Change theme to neon; bloom appears. Stop button visible.
6. Swipe right or tap backdrop: drawer dismisses.
7. Press home: app enters PiP; visualiser keeps running in the floating window.
8. Open Spotify in foreground; PiP floats above. Confirm audio still captures.
9. Tap the cycle-view button in PiP: view advances; toast not visible (hidden in PiP).
10. Tap the PiP window: app expands back to full-screen.
11. Swipe down to dismiss PiP: app stops cleanly.
12. Restart, tap Start, deny screen capture in the dialog: error message shows; tap Start again, allow: works.
13. Play a DRM-restricted source (if available): "No signal detected" hint appears.
14. Lock and unlock the phone mid-capture: capture survives.
15. Receive an incoming call during capture: capture continues; call audio is not captured.

## 15. Open questions

None at spec-write time. Decisions settled:

- Native audio loopback only (no microphone fallback).
- Min Android 14.
- Capacitor + custom plugin (not bare Android Studio, not full native rewrite).
- Auto-enter PiP on `onUserLeaveHint`; one RemoteAction (cycle view).
- Sideload distribution, self-signed APK.
- Full mobile UI redesign: swipe right = next view, swipe left = settings drawer.
- Base64 JSON event bridge for PCM; local WebSocket as documented fallback.
